Análisis Completo del Algoritmo ABC-SMC y sus Ejemplos

Este documento ofrece una explicación detallada del algoritmo ABC-SMC y su aplicación en los ejemplos del paper "Approximate Bayesian computation scheme for parameter inference and model selection in dynamical systems", adaptada para perfiles de ingeniería informática y de biología matemática.

Parte 1: El Algoritmo ABC-SMC Detallado

El objetivo del algoritmo es encontrar los valores más probables de los parámetros de un modelo (θ) dada una evidencia experimental (D_obs). En términos formales, busca aproximar la distribución a posteriori p(θ | D_obs).

Glosario de Conceptos Clave

Término Interpretación (Ingeniería Informática) Interpretación (Biología/Matemáticas)
Parámetro (θ) Las variables de configuración de tu función de simulación. El vector de parámetros del modelo que se desea inferir.
Partícula Un objeto o struct que contiene un juego completo de valores para los parámetros. Una hipótesis. Un punto θ^(i) en el espacio de parámetros.
Población Un array o list de N partículas. Un conjunto de N partículas {θ_t} que, en conjunto, aproximan una distribución de probabilidad.
Prior (π(θ)) Los rangos (mín/máx) que definen el espacio de búsqueda inicial para los parámetros. La distribución de probabilidad a priori, que encapsula nuestro conocimiento sobre θ antes de ver los datos.
Tolerancia (ε) Un umbral de error (float). Si error <= ε, la simulación es válida. El error máximo permitido. Define el soporte de la distribución objetivo en la generación t.
Kernel (K_t) Una función "jiggle" o "mutate" que modifica ligeramente una partícula (ej. añadiendo ruido gaussiano). Un kernel de transición K_t(θ'|θ) que define la probabilidad de pasar de la partícula θ a θ'.
Peso (w) Un float que indica la importancia de una partícula para el muestreo de la siguiente generación. El peso de importancia que corrige la diferencia entre la distribución de muestreo y la distribución objetivo.

El Algoritmo Paso a Paso

S1: Inicialización

Propósito: Configurar los parámetros de ejecución del algoritmo.

Interpretación (Ingeniería): Se definen las constantes y se prepara el bucle principal.

Tolerances = [50.0, 25.0, 10.0, 5.0, 1.0] # Umbrales de error decrecientes
N = 1000  # Tamaño de la población
current_t = 1 # Empezamos en la primera generación

Interpretación (Matemáticas): Se fija la secuencia de tolerancias ε_1 > ε_2 > ... > ε_T y el número de partículas N. Se inicializa el índice de población t=1.

S2.0: Inicio de una Generación

Propósito: Preparar las estructuras de datos para la nueva población.

Interpretación (Ingeniería): Se inicializan los arrays que contendrán las partículas y pesos de la generación t.

Population[current_t] = []
Weights[current_t] = []

Interpretación (Matemáticas): Se preparan los conjuntos para la población {θ_t} y los pesos {w_t}.

S2.1: Bucle de Propuesta y Selección de una Partícula

Propósito: Generar una partícula candidata y aceptarla si su simulación se parece lo suficiente a los datos reales.

Interpretación (Ingeniería): Se itera N veces para encontrar N partículas válidas.

for i in 1..N:
    while True: # Bucle hasta aceptar una partícula
        # 1. Proponer un candidato
        if current_t == 1:
            candidate = sample_from_prior_range()
        else:
            parent = weighted_sample(Population[t-1], Weights[t-1])
            candidate = jiggle_function(parent)

        # 2. Simular y medir error
        sim_data = model(candidate)
        error = distance(sim_data, observed_data)

        # 3. Aceptar o rechazar
        if error <= Tolerances[current_t]:
            # ¡Aceptada! Salir del bucle y procesarla en S2.2
            break

Interpretación (Matemáticas): Para cada i de 1 a N, se repite: se propone un candidato θ** (desde el prior π(θ) si t=1, o perturbando una θ* de la población anterior si t>1). Se acepta si d(D_sim, D_obs) <= ε_t.

S2.2: Almacenamiento y Cálculo del Peso

Propósito: Guardar la partícula aceptada y calcular su peso, que refleja su importancia y corrige sesgos del muestreo.

Interpretación (Ingeniería): Se añade la partícula al array de la población y se calcula su peso.

Population[current_t].add(candidate)

# --- Cálculo del Peso ---
if current_t == 1:
    # En la primera ronda, todas las soluciones son igual de importantes
    new_weight = 1.0
else:
    # El peso es la plausibilidad a priori dividida por la
    # probabilidad de haberla generado ("popularidad").
    numerator = prior_pdf(candidate) # La "altura" en el paisaje del prior
    
    denominator = 0.0
    for j in 1..N:
        old_particle = Population[t-1][j]
        old_weight = Weights[t-1][j]
        # La función "jiggle" debe poder decirnos la prob. de la transición
        transition_prob = jiggle_function.pdf(candidate | old_particle)
        denominator += old_weight * transition_prob
        
    new_weight = numerator / denominator

Weights[current_t].add(new_weight)

Interpretación (Matemáticas): Se añade θ** a {θ_t}. El peso w_t se calcula como w_t = π(θ**) / Σ[w_{t-1} * K_t(θ**|θ_{t-1})]. Si t=1, w_1 = 1. El numerador es el valor de la PDF del prior en el punto θ**. El denominador es la densidad de probabilidad de la mezcla de kernels de la población anterior, evaluada en θ**.

S3: Normalización y Siguiente Iteración

Propósito: Estandarizar los pesos para que sumen 1 y puedan usarse como una distribución de probabilidad para el muestreo de la siguiente generación.

Interpretación (Ingeniería):

# Al final del bucle for i in 1..N
total_weight = sum(Weights[current_t])
for j in 1..N:
    Weights[current_t][j] = Weights[current_t][j] / total_weight

# Pasar a la siguiente generación
current_t += 1

Interpretación (Matemáticas): Se normalizan los pesos w_t para que Σ(w_t) = 1. Se incrementa t. Si t <= T, se regresa a S2.0. Si no, el algoritmo finaliza y {θ_T} con sus pesos {w_T} es la aproximación de la distribución a posteriori.

Parte 2: Aplicación en Ejemplos del Paper

Resumen de los Ejemplos

  • Ejemplo 3.1 (Lotka-Volterra): Se utiliza un modelo clásico de depredador-presa para demostrar dos puntos clave del algoritmo ABC-SMC:
    1. Eficiencia: Es computacionalmente muy superior a métodos más simples, necesitando cientos de veces menos simulaciones para alcanzar un resultado preciso.
    2. Flexibilidad: Funciona sin cambios tanto para modelos deterministas (basados en Ecuaciones Diferenciales Ordinarias) como para modelos estocásticos (que usan simuladores como el Algoritmo de Gillespie).
  • Ejemplo 3.2 (Repressilator): Se emplea un modelo más complejo de un circuito genético para ilustrar la capacidad más avanzada del algoritmo:
    • Análisis de Sensibilidad y Estructura: Más allá de inferir parámetros, el método revela qué parámetros son cruciales para el comportamiento del sistema y cuáles son "identificables" con los datos experimentales disponibles. Proporciona un diagnóstico profundo sobre la relación entre el modelo y los datos, una herramienta muy potente para cualquier científico o ingeniero.

Ejemplo 3.1: Modelo Depredador-Presa de Lotka-Volterra

Este es el modelo "hola, mundo" de los sistemas dinámicos. Describe cómo las poblaciones de depredadores y presas interactúan y oscilan en el tiempo.

3.1.1: El Caso Determinista (Curvas Perfectas con Ruido)

Explicación (Ingeniería Informática):
  • Setup del Test:
    1. Generación de "Ground Truth": Se ejecuta el modelo con a=1 y b=1 para generar las curvas "verdaderas".
    2. Creación de "Datos Observados": Se toman solo 8 puntos de esas curvas y se les añade ruido aleatorio. Esto simula un experimento real, donde las mediciones son imperfectas y escasas.
    3. Función de Distancia: Se usa la Suma de Errores al Cuadrado (SSE) entre los 8 puntos de la simulación y los 8 puntos observados.
  • Benchmark de Rendimiento:
    • Fuerza Bruta (ABC Rejection): Necesitó 14.1 millones de simulaciones para encontrar 1000 partículas válidas. Extremadamente ineficiente.
    • ABC-SMC (el método del paper): Necesitó solo 52,194 simulaciones en total para obtener el mismo resultado, pero con mucha más precisión. Es ~270 veces más rápido.
  • Resultado: El algoritmo devuelve una población de 1000 structs de parámetros. Al hacer un histograma de los valores a y b de esos structs, se ve que se agrupan exactamente alrededor de (1, 1). El test pasa: el código funciona y es eficiente.
Explicación (Biología/Matemáticas):
  • Hipótesis: ¿Podemos recuperar los parámetros a y b del sistema a partir de datos escasos y ruidosos, que es el escenario experimental habitual?
  • Análisis de Eficiencia: Se compara el ABC-SMC con métodos más simples (rejection sampling, MCMC). Se demuestra que el enfoque secuencial reduce drásticamente el coste computacional, ya que guía la búsqueda hacia regiones de alta probabilidad posterior en lugar de explorar a ciegas el espacio del prior.
  • Resultado: La distribución a posteriori final para los parámetros a y b (Figura 2f del paper) está correctamente centrada en los valores verdaderos (1, 1) usados para generar los datos. Esto valida que el método es capaz de inferir los parámetros correctos del sistema dinámico.

3.1.2: El Caso Estocástico (Simulaciones inherentemente ruidosas)

Explicación (Ingeniería Informática):
  • Cambio en el model(): En lugar de un ODE solver, la función model() ahora usa el Algoritmo de Gillespie. Este es un método estándar para simular sistemas donde los eventos (nacimientos, muertes, reacciones) ocurren de forma aleatoria en el tiempo. Cada vez que lo ejecutas con los mismos parámetros, obtienes un resultado ligeramente diferente.
  • Parámetros: Los nuevos parámetros son (c1, c2, c3), que representan las propensiones de las reacciones estocásticas.
  • Resultado: El algoritmo funciona sin necesidad de cambiar su lógica principal. Se le pasa una función model() diferente y es capaz de encontrar los valores correctos para c1, c2, c3. Demuestra la modularidad y flexibilidad del framework ABC-SMC.
Explicación (Biología/Matemáticas):
  • Hipótesis: ¿Se puede aplicar el mismo formalismo a sistemas estocásticos, descritos por una Ecuación Maestra en lugar de ODEs? Los modelos estocásticos son a menudo más realistas para sistemas biológicos a nivel celular.
  • Metodología: El ABC-SMC es naturalmente compatible con modelos estocásticos, ya que solo requiere la capacidad de simular datos desde el modelo, no resolverlo analíticamente. El Algoritmo de Gillespie proporciona este mecanismo de simulación.
  • Resultado: Las distribuciones a posteriori para c1, c2, c3 (Figura 3) se centran correctamente en los valores verdaderos. Se demuestra que el ABC-SMC es un método general que no está limitado a un tipo particular de modelo matemático (determinista o estocástico).

Ejemplo 3.2: El Modelo Repressilator

Este es un modelo famoso de un circuito genético sintético. Tres genes se reprimen entre sí en un bucle, creando oscilaciones. Es más complejo, con 6 ecuaciones y 4 parámetros a inferir: θ = (α0, n, β, α).

3.2.1: El Caso Determinista y el Análisis de Sensibilidad

Explicación (Ingeniería Informática):
  • Setup del Test: Similar al anterior, pero con un giro: se simulan las 6 variables (3 mRNAs y 3 proteínas), pero la función de distancia solo usa los datos de los 3 mRNAs. Esto simula un experimento donde solo puedes medir una parte del sistema.
  • Resultado 2 (Análisis de "Inferibilidad"): Al observar cómo evoluciona la incertidumbre de cada parámetro a lo largo de las generaciones (Figura 4b), se ve que el error para el parámetro n baja muy rápido, mientras que el error para α apenas cambia.
    • Lección para el Ingeniero: Tus datos de entrada (los niveles de mRNA) contienen mucha información para averiguar n, pero casi ninguna para averiguar α. Si quisieras saber el valor de α, necesitarías un tipo de experimento diferente. El algoritmo te dice qué partes de tu modelo puedes identificar con los datos que tienes.
  • Resultado 3 (Análisis de Componentes Principales - PCA): Se aplica PCA a la población final de partículas (Figura 4d).
    • Lección para el Ingeniero: El PCA encuentra las "direcciones" más importantes en el espacio de parámetros. La "dirección" menos importante (el último componente principal) corresponde a la combinación de parámetros a la que el modelo es más sensible. En este caso, una combinación de n y β. Esto te ayuda a depurar y entender las dependencias ocultas en tu modelo complejo.
Explicación (Biología/Matemáticas):
  • Hipótesis: Además de la inferencia, ¿puede el método revelar propiedades estructurales del modelo, como la sensibilidad a los parámetros y la "identificabilidad" de los mismos?
  • Análisis de Sensibilidad Global: El seguimiento de las distribuciones marginales intermedias (de t=1 a T) proporciona un análisis de sensibilidad global "gratuito". Los parámetros cuyas distribuciones se contraen rápidamente (como n) son aquellos a los que el sistema es muy sensible y que los datos pueden identificar bien (son "identificables"). Los parámetros que apenas cambian (como α) son "sloppy" (descuidados).
  • Identificación de "Stiffness": El PCA sobre la distribución a posteriori final revela las combinaciones de parámetros "stiff" (rígidas) y "sloppy". El último eigen-vector (el de menor eigen-valor) apunta en la dirección del espacio de parámetros a la que el modelo es más sensible. Esto es análogo a calcular la matriz Hessiana en el máximo de la verosimilitud. Revela que la dinámica del sistema está fuertemente controlada por una combinación específica de n y β.
